# Codex Spec

$ARGUMENTS で渡された要件・機能名をもとに、Codex への委譲を前提とした設計書を作成する。

手順:

1. **codex-spec skill を使用する**（設計書の構造・テンプレート・チェックリストはすべて skill に従う）
2. 要件が曖昧な場合は、設計に着手する前にユーザーへ確認する
3. 既存コードの依存関係・影響範囲を調査する（Claude の 1M コンテキストを活かす）
4. ユニット間の契約（型・スキーマ・API）を先に固める
5. 独立した実装ユニットに分割し、各ユニットに成果物・受け入れ条件・境界・依存を明記した設計書を書く
6. 設計書を `docs/` 配下（or プロジェクトの慣習）に書き出す
7. レビューを促し、次アクションとして `/codex-impl <設計書パス>` を提示する

注意:

- 設計（アーキテクチャ・契約・受け入れ条件）は書き、実装詳細（関数の中身）は書かない
- ここで書く設計書がそのまま /codex-impl の委譲単位になる。ユニット分割の粒度が品質を決める

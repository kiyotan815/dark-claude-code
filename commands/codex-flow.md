# Codex Flow

$ARGUMENTS で渡されたタスクを、設計 → 委譲実装 → 監査まで一気通貫で実行する（`/codex-spec` + `/codex-impl` の一括版）。

手順:

1. 要件が曖昧で設計を固められない場合のみ、着手前にユーザーへ確認する（固められるなら途中で止まらない）
2. **codex-spec skill** で設計書を作成し `docs/` 配下に書き出す（ユニット分割・受け入れ条件・並列マップ）
3. 設計書の要点（ユニット一覧と並列計画）を短く提示し、確認は待たずにそのまま続行する
4. **codex-delegate skill** で各ユニットを `codex exec` に委譲する（競合しなければ worktree 並列）
5. 監査ループを回す — diff 自読・テスト再実行・NG は再委譲、収束しなければ Claude が引き取る
6. 結果を報告する: 設計書パス / ユニットごとの結果（成功・再委譲回数・引き取り） / 監査所見 / 残課題
7. **commit はユーザーの確認を得てから行う** — このフローは人間のレビューポイントが末尾に集約されるため、自動 commit はしない

使い分け:

- 中規模までの、要件が明確なタスク向け
- 大きな機能・リスクの高い変更は `/codex-spec` で設計書を出し、人間レビューを挟んでから `/codex-impl` に渡す（2段階運用）
- ルーティング基準で「Claude 直接」相当の小タスクだった場合は、委譲より直接実装が速い旨を伝えて直接実装してよい
